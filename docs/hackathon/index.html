Set up both laptopsOpen the three-minute script

Bring two laptops with speakers and microphones, both chargers, and the display adapter you plan to use. Assign one person to present and another to operate laptop B.

Set up both laptops

Repeat the setup on each laptop before the event. Keep both copies on the same revision. Run the commands one line at a time and resolve errors before continuing.

  1. Install Python 3.12 or 3.13 and Node.js 22. Check node --version and npm --version. Python · Node.js
  2. Sign into GitHub with access to the private SonicBridge repository. Choose Code → Download ZIP and extract it, or clone the repository.
  3. Open your terminal in the project folder. Check for requirements.txt and the web and sonicbridge folders.
Windows PowerShell 
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm.cmd --prefix web ci
npm.cmd --prefix web run build
.\.venv\Scripts\python.exe -m sounddevice
.\.venv\Scripts\python.exe -m uvicorn sonicbridge.app:app --host 127.0.0.1 --port 8000

If you installed Python 3.13, use py -3.13. If py is unavailable, check python --version and then use python -m venv .venv.

macOS and Linux

On Debian or Ubuntu, install the audio runtime and virtual environment package first.

sudo apt-get update
sudo apt-get install -y python3-venv libportaudio2

On macOS or Linux, run these from the project folder after confirming python3 --version.

python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm --prefix web ci
npm --prefix web run build
.venv/bin/python -m sounddevice
.venv/bin/python -m uvicorn sonicbridge.app:app --host 127.0.0.1 --port 8000

Check the build. On each laptop, leave Uvicorn running and open http://127.0.0.1:8000. In Simulation, send Ready with a blank passphrase. Look for the exact text under Received and All packets acknowledged in Packet log.

On show day, run only your OS’s final Uvicorn command. Keep the terminal open. Each browser uses its own laptop’s local URL.

Rehearse the live link

Start about 30 cm apart in a quiet room. Select built-in audio on both laptops and keep the speakers at moderate volume.

Laptop B · listen first

  1. Set Channel to Speaker + microphone.
  2. Choose Receive.
  3. Select the built-in mic and speaker or verify both system defaults. Leave the passphrase blank.
  4. Click Start listening. Confirm the status reads listening.

Laptop A · send second

  1. Choose Speaker + microphone → Send. Set the mic and speaker and leave the passphrase blank.
  2. Click Test link. Wait for Peer replied.
  3. Use Adaptive or the suggested profile. Type HELLO and click Transmit through sound.
  4. Check for All packets acknowledged on A and exact text under Received on B.

Repeat under stage conditions

  • Confirm A still plays through its local speaker when connected to the projector.
  • Close call apps and disconnect headsets. Rehearse with the same placement you plan to use.
  • After setup, repeat with Wi-Fi and Bluetooth off to check the offline claim.

Two directions matter. A reply proves B heard A and A heard B. If B gets the text but A times out, inspect B’s speaker and A’s mic.

Optional encrypted transfer

Stop B’s listener, enter the same passphrase of at least 12 characters on A and B, and restart listening on B. Send short text. B should mark it Authenticated. Use a throwaway demo phrase and type it off the projector.

The three-minute demo

Ask a judge for a word. Let them hear it travel. Then give them the Resume button.

0:00

Explain the link

“Two ordinary laptops exchange digital packets. One speaker sends the data. The other sends an acknowledgment.” Project A and have B listening already.

0:25

Send the judge’s word

Ask for 4–8 characters. After a successful backstage probe, click Transmit through sound. Show the matching inbox entry on B and the ACK on A.

1:05

Let a judge recover the transfer

Say “This next run uses controlled simulation.” Click Run loss & recovery demo. Point to two lost replies and the switch to Robust. When the saved transfer banner appears, let the judge click Resume transfer. Point out the first packet is already on the peer and the authenticated message appears once.

2:10

Show the profile trade-off

In Channel Lab, choose Interference and click Compare profiles. If time permits, repeat with Quiet. Show which profiles delivered the message and how much useful data they delivered per second in the simulation. Export CSV saves the results.

2:45

Close with the use case

“SonicBridge makes short offline exchanges possible with hardware people already have.”

Only 60 seconds? Run the labeled recovery simulation, show the retry and profile change, and let the judge click Resume.

Questions judges might ask

What changes in Robust mode?

Two pitches encode bits. Robust uses longer body symbols and error correction. Fast uses shorter body symbols. Every profile uses the same preamble and header.

How can a transfer survive a restart?

The sender saves one outgoing checkpoint. The receiver saves verified chunks. On resume, the sender requests the peer’s received-chunk bitmap and sends only missing chunks.

Can it send a file? How private is it?

The payload limit is 2,048 bytes. Optional shared-passphrase encryption protects the message contents in transit. Control packets are visible and the local inbox stores received contents in plaintext.

How far does it work?

Report only the distances and conditions you rehearsed. The lab shows simulated throughput and delivery. Physical range needs its own measurement.

Recover on stage

Try the probe again after one quick hardware check. If the room still wins, move to the controlled demo.

Probe times out or no one hears the tones

Check that B is listening. Unmute both speakers, select both built-in mics explicitly, bring the laptops closer, and try again. Check the OS microphone permission for the terminal or Python process and restart the service after a permission change.

Browser will not load the dashboard

Check the local Uvicorn terminal. If port 8000 is busy, use --port 8001 and open http://127.0.0.1:8001 on that laptop. If the page shows a 404, run the web build and restart Uvicorn. If PortAudio is missing on Debian or Ubuntu, install libportaudio2.

The peer cannot unlock the message

Stop B, correct its shared passphrase, and start it listening. On A, click Resume transfer.

Recovery demo button is disabled

Stop any active operation. If a saved transfer is in the way, resume it or discard its checkpoint. To preserve the checkpoint, use the other laptop for the demo after stopping its listener.

Switch to simulation. Say “We’re switching to a controlled simulation for the recovery sequence.” Click Run loss & recovery demo on an idle laptop with no saved transfer. You can show the same decoder, retry logic, and resume handshake without a live acoustic link.

Before you walk on

  • Both laptops plugged in and audio outputs checked.
  • B listening and A has passed the backstage probe.
  • Recovery demo rehearsed and no leftover checkpoint.
  • Judges invited to the private repo if access is required.
